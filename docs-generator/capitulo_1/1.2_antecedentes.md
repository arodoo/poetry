# 1.2 Antecedentes del Proyecto

Antes, el control de socios se basaba en procesos manuales. 
Eran esquemas técnicos rígidos. En lugares con muchos 
usuarios y distintas zonas de servicio, esta falta de orden 
genera riesgos. La calidad de los datos se pierde.

Poetry nace para enfrentar este escenario. Se identificó la 
necesidad de digitalizar el registro de miembros. Esto 
incluye la lógica para zonas de acceso y el seguimiento de 
códigos de venta externos. Es un paso necesario.

Previamente, se establecieron bases para separar las 
responsabilidades del código. Esto logró que el backend ya 
no fuera un bloque aislado. Ahora es una arquitectura que 
admite varios clientes. El avance logrado muestra que el 
proyecto está listo para entornos reales.
