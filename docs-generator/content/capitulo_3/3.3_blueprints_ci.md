# 3.3 Artefactos de Diseño Arquitectónico (Blueprints DDD)

Martin (2017) argumenta que la arquitectura
consiste en decisiones difíciles de revertir.
Poetry codifica estas decisiones en blueprints
JSON que prescriben la estructura obligatoria
de cada módulo.

El `backend-module-blueprint.json` dicta carpetas
`domain/`, `application/` e `infrastructure/` por
módulo, segregando entidades, casos de uso y
adaptadores. El `frontend-module-blueprint.json`
impone la misma separación en el lado cliente con
`components/`, `hooks/` y `services/`.

Un validador (`check:backend-modules`) compara la
estructura real contra el blueprint antes de cada
commit. Si un directorio viola la convención, el
commit se rechaza de inmediato.

### 3.3.1 Diagrama de Pipeline CI/CD

La automatización del aseguramiento se ejecuta
en trece etapas secuenciales. Un fallo en
cualquier punto detiene el proceso e impide la
contribución al repositorio.
