# 3.4 Contratos de Integración (OpenAPI y SDKs)

Fowler (2010) acuñó el término «Consumer-Driven
Contracts» para describir la práctica de definir
la interfaz antes de implementarla. Poetry aplica
este principio con una especificación OpenAPI v3
alojada en `docs/api/openapi-v1.yaml`.

La autenticación emplea JWT sin estado. Al iniciar
sesión, el servidor firma un token con los roles
del usuario (RBAC). El backend valida la firma
criptográfica en cada petición, eliminando la
necesidad de almacenar sesiones en memoria.

Validadores de Zod actúan en tiempo de ejecución
y React Query con claves estables complementa la
barrera contra la deriva entre capas, que Newman
(2015) identifica como el riesgo principal en
arquitecturas distribuidas.
