### 3.2.2 Interacción y Flujo de Control

Para ilustrar el funcionamiento, analicemos el flujo de un 
registro de acceso. Aunque el flujo de control viaja desde 
la web hacia la base de datos, las dependencias de código 
viajan en sentido opuesto (Inversión de Dependencia).

1. **Petición**: El frontend envía un JSON con el ID del 
usuario al `AccessController` (Infraestructura).
2. **Orquestación**: El controlador invoca al caso de uso 
`RegisterAccess` (Aplicación).
3. **Reglas de Negocio**: El caso de uso consulta al 
`MemberRepository` (puerto en Dominio) para recuperar la 
entidad `Member`.
4. **Estado**: La entidad `Member` verifica sus propias 
reglas (ej. "¿Estoy activo?", "¿Tengo deuda?").
5. **Persistencia**: Si es válido, el caso de uso llama al 
`AccessLogRepository` para guardar. La implementación real 
(JPA) se inyecta en tiempo de ejecución, invisible para el 
dominio.
