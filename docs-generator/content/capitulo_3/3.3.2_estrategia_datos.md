### 3.3.2 Estrategia de Indexación y Rendimiento

Dado que el requerimiento de latencia es estricto, el diseño 
físico de la base de datos incluye índices estratégicos. 
No basta con indexar las claves primarias.

Se han creado índices compuestos en la tabla `subscriptions` 
sobre los campos `(member_id, status, end_date)`. Esto 
permite verificar si un usuario está activo sin necesidad de 
leer la tabla completa (Index Only Scan). Para la tabla de 
logs, se utiliza particionamiento por rangos de fecha, 
archivando registros de meses anteriores en tablas históricas 
para mantener ligero el conjunto de datos "caliente" (hot data) 
del día a día.
