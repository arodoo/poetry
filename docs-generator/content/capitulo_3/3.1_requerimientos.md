# 3.1 Especificación de Requerimientos

La construcción de Poetry responde a necesidades técnicas 
claras. No se trata solo de registrar datos. Se busca un 
control operativo firme.

### 3.1.1 Requerimientos Funcionales
- **Gestión de Socios**: El software debe permitir el alta, 
baja y consulta de miembros con estados en tiempo real.
- **Validación Biométrica**: El ingreso físico se valida 
mediante un lector de huella dactilar integrado. La huella 
es la llave.
- **Control de Zonas**: Definición de áreas de acceso por 
tipo de membresía. No todos entran a todos lados.
- **Rastreo de Ventas**: Uso de códigos de vendedores para 
atribuir cada suscripción de forma automática.

### 3.1.2 Requerimientos No Funcionales
- **Seguridad**: Los datos de acceso deben estar protegidos 
en todo el flujo.
- **Escalabilidad**: El diseño debe admitir nuevos módulos 
sin reescribir el núcleo.
- **Rendimiento**: La respuesta del API ante un intento de 
aceso debe ser casi inmediata. La rapidez es clave.
