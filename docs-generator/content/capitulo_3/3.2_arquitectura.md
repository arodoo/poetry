# 3.2 Arquitectura del Esquema

Poetry adopta un diseño por capas. El objetivo es el 
desacoplamiento técnico total.

### 3.2.1 Capa de Dominio
Es el corazón del software. Aquí residen las Entidades 
como Miembro y Zona. No dependen de nada externo. Se usan 
Objetos de Valor para asegurar que cada dato sea válido por 
definición. La lógica de negocio vive aquí, protegida.

### 3.2.2 Capa de Aplicación
Orquesta el flujo de información. Aquí se encuentran los 
Casos de Uso. Un ejemplo es el proceso de "Validar Acceso". 
Esta capa conoce qué debe pasar, pero no cómo se guarda en el 
disco duro. Usa DTOs para mover datos de forma segura.

### 3.2.3 Capa de Infraestructura
Contiene los detalles de implementación. Aquí están los 
Repositorios que hablan con PostgreSQL y los Adaptadores 
para el lector de huella. Es la capa más externa. Si se deba 
cambiar el hardware, solo se toca este nivel técnico. El 
negocio no se entera del cambio.
