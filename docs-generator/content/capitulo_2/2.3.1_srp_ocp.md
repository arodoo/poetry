# 2.3 Principios SOLID

La calidad del código orientado a objetos no es subjetiva. 
Existen métricas y principios claros. SOLID es el acrónimo 
que agrupa las cinco reglas cardinales para el diseño de 
software mantenible, popularizadas por Robert C. Martin (2002).

### 2.3.1 Responsabilidad Única (SRP)
Suele malinterpretarse como "hacer una sola cosa". Su 
definición real es más sociológica: "Un módulo debe tener 
una sola razón para cambiar". Si un cambio en el reporte de 
cuentas obliga a modificar la clase de autenticación, se 
viola este principio. Separar responsabilidades reduce el 
miedo a tocar código antiguo.

### 2.3.2 Abierto/Cerrado (OCP)
El software debe estar abierto a la extensión pero cerrado a 
la modificación. Este es el corazón de la arquitectura de 
plugins. En Poetry, agregar un nuevo tipo de membresía no 
debería implicar reescribir el validador de accesos. Se 
crea una nueva clase que extiende el comportamiento base, 
sin riesgo de romper lo que ya funciona.
