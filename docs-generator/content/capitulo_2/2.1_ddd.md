# 2.1 Domain-Driven Design (DDD)

El desarrollo de software a gran escala exige un lenguaje 
común. DDD resuelve esto. No es una mera técnica. Es un 
enfoque que sitúa las reglas del negocio en el centro del 
universo técnico. Así, la lógica del problema guía cada 
decisión del código.

En Poetry, esta filosofía segmenta la complejidad técnica. 
Se definen contextos delimitados. Esto asegura que un Miembro 
en la zona de acceso signifique lo mismo para el backend que 
para el reporte de ventas. La coherencia conceptual es el 
pilar. Se evitan las fugas de lógica entre módulos.

El uso de Entidades y Objetos de Valor (Value Objects) 
permite modelar la realidad con rigor. Un correo electrónico 
no es solo una cadena de texto. Es un concepto con reglas 
propias de validación. Esta estructura técnica garantiza que 
el núcleo del software sea inmune a cambios accidentales en 
la base de datos.
