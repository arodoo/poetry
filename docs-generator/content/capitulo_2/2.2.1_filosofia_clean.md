# 2.2 Arquitectura Limpia (Clean Architecture)

### 2.2.1 Independencia como Objetivo

A lo largo de la historia del software, han surgido varias 
arquitecturas: Hexagonal, Onion, Screaming. Robert C. Martin 
(2017) las sintetizó en lo que hoy llamamos Arquitectura 
Limpia. Aunque varían en detalles, todas comparten un 
objetivo: la separación de intereses.

La filosofía central es que el software debe ser independiente 
de los frameworks. Spring Boot o React son instrumentos 
útiles, pero no deben dictar cómo funciona el negocio. El 
producto también debe ser independiente de la base de datos y 
de la interfaz de usuario.

En Poetry, esto significa que la lógica de "Autorizar 
Entrada" no sabe si los datos vienen de una web o de un 
lector biométrico. No le importa si se guardan en SQL o en 
un archivo de texto. Esta apatía técnica es deliberada. Es 
lo que permite que el software sobreviva al paso del tiempo.
