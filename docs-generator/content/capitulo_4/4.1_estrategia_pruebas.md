# CAPÍTULO 4. RESULTADOS Y CONCLUSIONES

# 4.1 Estrategia de Pruebas y Validación

La validación del sistema no se limitó a una verificación 
funcional final, sino que siguió la estrategia de la 
Pirámide de Pruebas (Cohn, 2009), asegurando calidad en 
cada granularidad del código.

### 4.1.1 Pruebas Unitarias (Backend)
Se utilizó JUnit 5 y Mockito para aislar la lógica de 
dominio. Las Entidades y Casos de Uso cuentan con una 
cobertura de código superior al 80%. Se validaron reglas 
invariantes, como "un usuario no puede tener dos membresías 
activas simultáneas", sin levantar el contexto de Spring, 
lo que garantiza una ejecución en milisegundos.

### 4.1.2 Pruebas de Integración (API)
Mediante `SpringBootTest`, se verificó la interacción real 
entre los controladores REST y la base de datos H2 en 
memoria. Estas pruebas aseguran que los contratos OpenAPI 
se respetan y que el mapeo ORM (Hibernate) es correcto 
para las transacciones ACID.

### 4.1.3 Pruebas End-to-End (Frontend)
Utilizando Playwright, se automatizaron flujos críticos 
desde la perspectiva del usuario. El escenario "Registro de 
Nuevo Socio con Huella" se ejecuta en un navegador Headless 
en el pipeline de CI/CD, garantizando que ninguna regresión 
rompa el flujo principal de ingresos del negocio.
