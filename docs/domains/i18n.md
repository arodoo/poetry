# I18n Domain

## Overview

Handles internationalization and localization for the Poetry application.
Manages translation keys, language switching, and locale-aware routing.

---

## Entities

- `TranslationKey` — dot-separated string `ui.<feature>.<key>`
- `Locale` — `'en'` | `'es'`

---

## Business Rules

- All UI text must use i18n keys (no hardcoded strings in TSX).
- Locale priority (highest → lowest):
  1. **URL path segment** — `/es/login` → `'es'` (read synchronously on
     first render via `getCurrentLocale()`)
  2. **Backend preference** — `GET /api/v1/me/locale` (async, may override
     URL only on success with a valid locale)
  3. **Env default** — `VITE_DEFAULT_LOCALE` (used only when both URL and
     backend are unavailable)
- If the backend call fails (e.g. 401 on unauthenticated pages), the URL
  locale is preserved as fallback — the env default is never imposed over
  an explicit URL locale.

---

## Use Cases

- **Change language** — `setLocale(locale)` on `I18nCtx`
- **Add new translations** — add keys to `features/<name>/locales/en.json`
  and `es.json`; import and spread into `shared/i18n/catalog/en/index.ts`
  and `es/index.ts`

---

## Locale Resolution Flow

```
App mount
  └─ I18nProvider
       └─ useLocale()
            ├─ useState( getCurrentLocale() )   ← URL path, synchronous
            └─ useEffect → loadUserLocale()      ← async, backend
                  ├─ success + valid  → setLocale(backendLocale)
                  ├─ success + invalid→ setLocale(getDefaultLocale())
                  └─ failure          → setLocale(getCurrentLocale()
                                          || getDefaultLocale())
```

`getCurrentLocale()` (`shared/routing/localeUtils.ts`) reads
`window.location.pathname` with regex `/^\/([a-z]{2})(\/|$)/`.

## Catalog Structure

```
shared/i18n/
  catalog/
    en/index.ts   imports all en.json files, spreads into enCatalog
    es/index.ts   imports all es.json files, spreads into esCatalog
  catalogs.ts     ensureMessages(locale, fallback) → Messages
  generated/
    keys-features-*.ts   key slices (documentation — not type-enforced)
    keys.ts              I18nKey = string (readonly string[] annotation)
```

> **Note:** `I18nKey` resolves to `string` because `I18N_KEYS` is typed
> `readonly string[]` (not `as const` tuple). The union of literal strings
> is not enforced at compile time. Key correctness is validated at runtime
> via the catalog lookup.

## Key Naming Convention

```
ui.<featureName>.<sub>.<name>

Examples:
  ui.publicLogin.title
  ui.publicLogin.brand.tagline
  ui.adminStats.kpi.active
  ui.nav.logout
```

---

## Note: translate domain keys at the UI boundary

When rendering domain keys (chart axes, table rows), map them through the
translator before passing to the component:

```ts
const chartData = formatBarData(
  Object.fromEntries(
    Object.entries(data).map(([k, v]) => [t(`ui.charts.events.${k}`), v])
  ),
  'type',
  'count'
)
```

---

## Note: runtime catalog must include feature keys

If you add translation keys to a feature's `locales/*.json`, ensure the
shared runtime catalog imports or aggregates them so `t(...)` can resolve
those keys at runtime (see `src/shared/i18n/catalog/*`). Missing catalog
entries will cause components to display raw keys even if feature JSONs
contain the translations.
