# I18n Domain

## Overview
Handles internationalization and localization for the Poetry application. Manages translation keys, language switching, and locale-aware routing.

## Entities
- TranslationKey
- Locale

## Business Rules
- All UI text must use i18n keys
- Users can switch languages at any time

## Use Cases
- Change language
- Add new translations

## Dependencies
- None

## Status
- Implemented

## Note: translate domain keys at the UI boundary

When rendering domain keys (chart axes, table rows), map them through the translator before passing to the component, for example:

```ts
const chartData = formatBarData(
  Object.fromEntries(
    Object.entries(data).map(([k, v]) => [t(`ui.charts.events.${k}`), v])
  ),
  'type',
  'count'
)
```

This ensures labels use existing locale messages instead of raw backend keys.

## Note: runtime catalog must include feature keys

If you add translation keys to a feature's `locales/*.json`, ensure the
shared runtime catalog imports or aggregates them so `t(...)` can resolve
those keys at runtime (see `src/shared/i18n/catalog/*`). Missing catalog
entries will cause components to display raw keys even if feature JSONs
contain the translations.
